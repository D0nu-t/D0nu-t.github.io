TinyNLA — Natural Language
Autoencoder for Small Models

A language model's internal state at any word is a long list of numbers. TinyNLA trains one model to describe those numbers in plain English and a second to rebuild them from the description alone. If the rebuild is close, the description carried real information out of the model.

The idea

When a language model reads a sentence, it builds an internal state at every word: a vector of numbers holding what it has inferred so far and what it expects next. Most tools for studying these states work on the numbers directly.

A Natural Language Autoencoder (NLA) takes a different route, introduced in Anthropic's paper Natural Language Autoencoders Produce Unsupervised Explanations of LLM Activations (May 2026). One model, the verbalizer, sees only the numbers and writes an English explanation. A second, the reconstructor, sees only that explanation and tries to rebuild the numbers.

An analogy: it's like describing a painting over the phone and scoring the copy the other person paints. A good copy means the description carried the picture.

TinyNLA is a from-scratch build of that method for small models, on a 4 GB laptop GPU. The paper worked with far larger models and far more compute; the question here is how much of the effect survives at this scale.

How it works Built

Data
Web text→GPT-2 state at one word, layer 8→Starter summary (Qwen2.5-0.5B)
Verbalizer
State injected as one token→Writes an explanation
Reconstructor
Reads the explanation→GPT-2's own first 8 layers→Rebuilt state
Training
Supervised warm-start→Reinforcement learning (GRPO)
Score
Fraction of variance explained

Both models start from summaries of the input text, written by a small model. Reinforcement learning then rewards the verbalizer for explanations the reconstructor can rebuild from. GRPO is a critic-free method: each sampled explanation is scored against the others in its group.

Results GPT-2 small

Scores are the fraction of variance explained, where 1 is a perfect rebuild. Rebuilds are forced to a fixed length, so even the best blind guess scores below zero. That blind guess, not 0, is the floor. Tested on 500 states never seen in training:

Fed to the reconstructorScorePlain meaning
The explanation of a different text−0.321Worse than nothing: a confident wrong description misleads
Nothing (average guess)−0.184The floor
A summary of the actual input text−0.099Knowing what the text says helps a bit
The verbalizer's explanation (numbers only)+0.005Helps the most

On the scale from the floor to a perfect rebuild, text summaries close about 7% of the gap and the verbalizer about 16%. The verbalizer scored −0.045 after the first 1,500 reinforcement-learning steps and +0.005 after 1,500 more, and it was still improving when training stopped.

Why this matters: explanations written from the model's internal state alone describe that state better than a summary written with the text in hand. Something that only guessed the topic couldn't do that.

Can it catch a thought that isn't in the text?

In a second test, a concept (weddings, space, dogs and seven others) is planted inside GPT-2 by nudging its internal state, while the text stays unchanged. Someone reading only the text would guess right 10% of the time.

Thought Reader Built

A local web tool for reading the model at any word. You type text, click a word, and the verbalizer writes several explanations of GPT-2's state at that point. Each one is scored by how well the reconstructor rebuilds the real state from it, and words that recur across explanations are highlighted, because recurring themes are the ones to trust.

Plain-language reports v0

Per-word reads are for specialists. The report view answers a simpler question for everyone else: what was the model thinking when it wrote this? You give it a prompt and get a verdict, a one-paragraph summary, and themes sorted into "in the text", "beyond the text" and "a name the text never mentions".

People tend to over-trust explanations of AI systems, so each read carries a reliability label. The label was checked by reading 300 states twice: the label from the first read predicts how good the second read is.

Reliability labelShare of readsScore of a fresh read
None64%−0.25
Moderate26%+0.18
Strong10%+0.35

So about a third of single reads are trustworthy, and the tool can tell which ones.

Limits

  • The signal is weak. 16% of the way to a perfect rebuild, against 60–80% in the original paper, which used much larger models, stronger starting summaries and far more compute.
  • Single explanations are unreliable. Trust themes that recur across samples and neighbouring words, not individual claims.
  • GPT-2 doesn't reason step by step, so checking whether a model's stated reasoning matches its internal state needs a larger model.
  • Not every check is scored yet. Five of the nine planned sanity checks are automated; all five pass.

Goals

  • More training — the score was still rising at the end of both runs.
  • Better starting summaries — written by a stronger model than the 0.5B one used so far.
  • A reasoning model — move to Qwen 0.5B with LoRA to read step-by-step reasoning.
  • A reader study — test whether people without an ML background interpret the reports correctly.
